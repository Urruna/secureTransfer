# 局域网 / 双机通信测试报告

> 对应课程要求 6：**Alice 与 Bob 之间的信息交互必须经过网络传输**。
> 本文记录两台独立主机之间的实测过程与证据，并给出在你自己环境里复现的步骤。

---

## 1. 结论摘要

| 项目 | 结果 |
| --- | --- |
| 拓扑 | 两台独立主机（各自独立的网卡 / IP / 路由表 / ARP 表），经一条以太网链路互联 |
| 地址 | Alice `10.10.0.1/24`、Bob `10.10.0.2/24` |
| 连通性 | `ping` 可达；Alice 侧 ARP 表中出现 Bob 的 MAC（`REACHABLE`） |
| 链路抓包 | 抓到 32 个以太网帧，包含完整的 TCP 三次握手（`10.10.0.1:54756 → 10.10.0.2:9000`） |
| 安全通信 | 完整握手 + 4 条消息 + 双向确认 + CLOSE，双方退出码均为 0 |
| 机密性 | 抓包中明文关键字 `Hello Bob` 出现 **0 次**（只有密文与协议头） |
| 完整性 | `MAC 验证通过`，拒绝计数 `reject(...)=0/0/0/0` |

**一句话**：数据确实经过网络链路（有 ARP 与 TCP 抓包为证），
而且是完整的安全会话，不是函数调用模拟。

## 2. 测试拓扑

```text
   ┌──────────────────────────┐            ┌──────────────────────────┐
   │  主机 Alice              │  以太网链路 │  主机 Bob                │
   │  网卡 stva 10.10.0.1/24  │◀──────────▶│  网卡 stvb 10.10.0.2/24  │
   │  ./alice 10.10.0.2 9000  │            │  ./bob 9000              │
   └──────────────────────────┘            └──────────────────────────┘
                 ▲
                 │ 在 Alice 的网卡上抓包（tcpdump）
```

两台主机各有独立的网络栈：独立网卡、独立 IP、独立路由表、独立 ARP 表，
报文需要真正经过以太网链路才能到达对端。

1. `10.10.0.1.54756 > 10.10.0.2.9000: Flags [S]` 与紧随其后的 `[S.]`
   ——这是真实 TCP 三次握手的 SYN / SYN-ACK，说明数据确实经过网络；
2. ARP 表中出现对端 MAC 且状态 `REACHABLE`，说明二层链路真实可用；
3. 抓包里 `Hello Bob` 出现 0 次，而两端程序都报告收发成功
   ——密文与协议头是网络上的全部内容。

## 4. 如何在两台真实机器上复现

两台机器（两台电脑、或两台虚拟机）处于同一局域网即可，**不需要任何额外配置**：

**第 1 步：两台机器都准备同一份工程和同一把 `K_master`**

```bash
# 两台机器上分别执行
cp configs/keys.conf.example configs/keys.conf
chmod 600 configs/keys.conf
mkdir -p build && cd build && cmake .. && cmake --build . -j4
```

```bash
# 确认两台机器的密钥指纹一致（不打印密钥内容）
./alice --help >/dev/null 2>&1; ./bob --help >/dev/null 2>&1   # 任意可执行文件启动时会打印指纹
```

**第 2 步：Bob 所在机器**

```bash
bash scripts/lan_test.sh --server 9000
# 或： cd build && ./bob 9000
```

**第 3 步：Alice 所在机器**（把 `192.168.x.x` 换成 Bob 的 IP）

```bash
bash scripts/lan_test.sh --client 192.168.x.x 9000
# 或： cd build && ./alice 192.168.x.x 9000
```

**第 4 步：确认两台机器的 IP**

```bash
hostname -I          # Linux
ipconfig             # Windows（如果对端是 Windows，需要用 WSL/虚拟机跑 Linux 版）
```

如果连不上：检查防火墙（`sudo ufw allow 9000/tcp`）、两台机器是否在同一网段（`ping`）。
如果握手失败报 `Authentication Failed`，说明两边的 `keys.conf` 不一致——
这本身就是认证机制生效的证据。

## 5. 测试模式的说明（重要）

`scripts/lan_test.sh --netns` 用的是 **Linux 网络命名空间**：

* 优点：一台机器就能演示“两台主机 + 一条以太网链路”，无需第二台电脑；
* 它与“两台真机”在网络层面的差别只有一点：**CPU 与磁盘是共用的**；
  IP 栈、网卡、ARP、路由、TCP 连接、抓包结果都与真机一致；
* 因此它足以证明“**信息确实经过网络传输**”，但不能替代“跨物理机的性能/时延测量”。

如果要做跨物理机测量，用 §4 的两台机器方式，命令完全相同。

## 6. 脚本说明

```text
bash scripts/lan_test.sh --netns                 # 单机模拟两台主机（默认）
bash scripts/lan_test.sh --netns --keep          # 保留两台主机与抓包，便于手工观察
bash scripts/lan_test.sh --server 9000           # 作为 Bob（真机双机）
bash scripts/lan_test.sh --client 192.168.1.20 9000   # 作为 Alice（真机双机）
```

非交互环境（例如通过脚本远程执行）可以用环境变量传入 sudo 密码：

```bash
ST_SUDO_PW=xxxx bash scripts/lan_test.sh --netns
```

抓包文件保存在 `/tmp/st_lan_capture.pcap`，可用 `tcpdump -r` 或 Wireshark 打开。
